# Создание Supabase с нуля

Демо работают без базы данных. Следующие шаги нужны для реальных ресторанов, заявок и административной панели.

1. Откройте https://supabase.com и войдите через GitHub.
2. Нажмите **New project**, выберите организацию или создайте её.
3. Назовите проект `dasturxon`. Задайте сильный пароль базы данных и сохраните его у себя в менеджере паролей. Не отправляйте пароль в чат и не добавляйте в GitHub.
4. Выберите доступный регион и тариф, дождитесь создания проекта.
5. В разделе **Connect** или настройках API найдите **Project URL** и **Publishable key** (`sb_publishable_...`; в старых проектах — public `anon` key). Не используйте `service_role` или secret key для `NEXT_PUBLIC_*`.
6. На своём Mac скопируйте `.env.example` в `.env.local` в корне проекта. Заполните URL и public publishable key. Файл `.env.local` исключён из Git.
7. В этой облачной среде откройте **Редактировать окружение** и задайте те же две переменные: `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Сохраните настройки. Значения ключей не нужно отправлять в чат.
8. В Supabase откройте **SQL Editor → New query**. Вставьте содержимое `supabase/migrations/202610090001_initial_schema.sql` и нажмите **Run** один раз. Миграция выполняется одной транзакцией; после успешного запуска повторно её не запускайте. Затем отдельным запросом выполните `202610090002_editors_and_settings.sql` один раз. Если первая миграция уже выполнена, запускайте только вторую.
9. В **Authentication → Users** создайте своего администратора. Отключите публичную регистрацию пользователей в настройках Auth. Скопируйте UUID пользователя.
10. В SQL Editor выполните, заменив текст UUID на настоящий идентификатор:

```sql
insert into public.admins (user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ') on conflict (user_id) do nothing;
```

В SQL Editor администратор базы может назначать права. В браузере пользователь не может добавить себя в таблицу `admins`.

11. Для доступа из облачной среды разрешите в настройках сети точный hostname проекта: `<project-ref>.supabase.co`. Существующие разрешения не удаляйте.
12. Сообщите в чате, что проект создан и настройки сохранены. Можно прислать только Project URL: это публичный адрес, необходимый для проверки сетевого доступа. Пароли и секретные ключи не присылайте.

## Что подготовлено

Таблицы ресторанов, категорий, блюд, заявок и разрешённых администраторов; UUID, внешние ключи, индексы, проверки цен и локализованных полей, RLS. Категория и блюдо должны принадлежать одному ресторану. Публично доступны только опубликованные данные, видимые категории и неархивные блюда. Ссылка ресторана сохраняется при переименовании. Фотографии черновиков находятся в приватном Storage bucket с ограничением 5 МБ и JPG/PNG/WebP.

Подготовлены серверное подключение приложения и защищённая административная панель. Проверка вашего реального Supabase Auth/Storage ещё требуется. Пароль базы данных для обычной работы приложения не используется.

## Вход в новую административную панель

Обновите проект с GitHub, сохранив свой `.env.local`. Затем выполните `npm ci` и перезапустите `npm run dev`.
Откройте `/admin` на локальном сайте: приложение перенаправит на `/admin/login`.

Email и пароль для входа — данные пользователя из **Supabase → Authentication → Users**, не пароль базы данных.
Если пользователя ещё нет, создайте его через **Add user → Create new user**. Добавьте его UUID в таблицу `admins` SQL-командой из пункта 10. Прав администратора по одному email недостаточно.

Для проверки вашего подключения без вывода ключей выполните:

```bash
npm run supabase:check
```

Проверка читает `.env.local`, обращается к реальным таблицам через публичный ключ и проверяет ограничение чтения `admins`.
Она не проверяет пароль администратора или Storage API. После изменения `.env.local` всегда перезапускайте dev-сервер.

В панели есть редакторы ресторанов, категорий и блюд, фотографии, порядок показа, наличие, скрытие/архив и массовые операции. Демо не импортируются в рабочую базу.

Откройте `/admin/restaurants/new`, создайте ресторан, заполните телефон, адрес и часы на двух языках. Добавьте видимую категорию и блюдо, затем выберите статус «Опубликован». Ссылка меню `/r/slug` появляется в редакторе. Черновик и архив публично недоступны.

В `/admin/settings` находятся контакты, договорная стоимость и черновики оферты/политики. Черновики с незаполненными реквизитами и пометками не публикуются. Заполните поля в квадратных скобках, удалите пометку черновика, проверьте оба перевода и включите публикацию.
